Sobre o Projeto

Scrapers tradicionais dependem de seletores CSS/XPath frágeis que quebram facilmente com mudanças de layout. Este projeto resolve esse problema utilizando um pipeline semântico com modelos de linguagem (LLMs) e validação estruturada com Pydantic, permitindo extrair dados imobiliários padronizados de qualquer portal do mundo sem necessidade de criar scrapers específicos para cada site.

Tecnologias Utilizadas

Python 3.10+ Google Gemini API Groq Cloud Streamlit Pydantic Playwright BeautifulSoup4 Pandas DuckDuckGo Search

Desafios de Engenharia & IA

  • Limites de Taxa e Micro-Batches: Modelos em camadas gratuitas ou de menor custo (como Groq) impõem limites severos de requisição e TPM (ex: 6.000 TPM). Foi necessário arquitetar processamento em micro-batches com throttling inteligente para não estourar quotas.
  • Condensação de Texto & Economia de Tokens: O HTML bruto de portais consome dezenas de milhares de tokens desnecessários. Modifiquei o scraper para realizar limpeza prévia do DOM, reduzindo cerca de 75% do ruído antes de enviar o payload para a IA.
  • Vícios de Modelos (ex: Módulo <think> do Qwen): Certos modelos de raciocínio inserem blocos não solicitados de reflexão (<think>) que poluem a resposta. Desenvolvi tratamentos de sanitização para garantir JSONs puros prontos para desserialização.
  • Modelos Menores e Necessidade de Ancoragem Rígida: Modelos mais compactos e baratos tendem a alucinar ou ignorar campos sem constraints severas. Implementei técnicas rigorosas de ancoragem de prompt e validação com Pydantic para manter a integridade dos dados.
